# TerrainSketch

緊急踏査（landslide field survey）用の完全オフライン地形スケッチ PWA。
GhContourPdf / TerrainMap（Rhino 8 / Grasshopper プラグイン）が出力する Geospatial PDF 白図に
iPad で現地スケッチを描き、**DXF / Geospatial PDF / ZIP 一式**で CAD・報告書へ渡す。

**処理はすべて端末内で完結する。図面・写真・位置情報を外部へ送信しない。**
配信サーバは初回のアプリ本体の受け渡しにしか使われない。

---

## 1. これは何のリポジトリか

`index.html` は**ライブラリを全て内包した単一 HTML（約 2.5 MB）**で、これ 1 つでアプリが動く。
このリポジトリは、その単一 HTML を GitHub Pages で配信し、
**iPad のホーム画面アプリ（PWA）としてインストール・更新できるようにするための足回り**。

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体。これだけダウンロードすれば `file://` でも動く |
| `sw.js` | Service Worker。**圏外でも起動できるようにする**（このリポジトリの存在理由） |
| `manifest.webmanifest` | PWA マニフェスト。ホーム画面アプリとしての名前・アイコン・表示モード |
| `icon-192.png` / `icon-512.png` / `icon-maskable-512.png` | アイコン |
| `.nojekyll` | GitHub Pages の Jekyll 処理を無効化 |

`index.html` は **file:// でも https でも同じファイルが動く**。実行時に `location.protocol` を見て、
https のときだけ Service Worker を登録する。ローカルファイルとして開いた場合は
ネットワークに一切触れない（従来どおりの完全ローカル動作）。

## 2. GitHub Pages の設定（初回のみ）

1. リポジトリに上記ファイル一式を push（ルート直下）
2. **Settings → Pages → Build and deployment**
   - Source: `Deploy from a branch`
   - Branch: `main` / `/ (root)`
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される

Actions は不要。ファイルを push するだけで反映される。

> **リポジトリの公開範囲について（v0.53 訂正）**
> GitHub Pages は Free プランでは **public リポジトリでしか使えない**。
> private リポジトリからでも公開できるのは Pro / Team 以上だが、
> **どちらの場合もサイト自体は誰でも見られる**（非公開にする機能ではない）。
> つまり **URL を知っている人はアプリのソースを読めるし、機能も使える**。
> アクセス制限が必要なら Cloudflare Pages + Access（50 人まで無料）を使う。
> 業務成果物としてそれが許容できるかは、公開前に社内で確認すること。
> 図面・写真などの業務データがリポジトリに入ることは無い（アプリは端末内処理のみ）が、
> 実データを間違って commit しないよう `.gitignore` は必ず設定する。

## 3. iPad での導入手順（現場担当者向け）

**必ず「ホーム画面に追加」まで行うこと。** ブラウザのタブで開いたままだと、
iOS は 7 日間アクセスの無いサイトのキャッシュを削除するため、**圏外の現場で起動しなくなる**。
ホーム画面アプリとして追加した場合はこの削除の対象外になる。

1. **電波の届く場所で** Safari で公開 URL を開く
2. 画面が完全に表示されるまで待つ（本体 2.5 MB のダウンロードとキャッシュ保存）
3. 共有ボタン → **「ホーム画面に追加」**
4. ホーム画面のアイコンから起動する
5. ☰メニュー最下部で **「ホーム画面から起動（オフライン対応）」** と表示されていることを確認
6. **機内モードにして起動できることを現場に出る前に必ず確認する**

## 4. 更新の出し方・入り方

### 出す側

0. アイコンを変えるときは `icon_src.png` を差し替えて `python3 mkicon.py`
1. `patch_vXXX.py` で `template.html` を編集
2. `build.py` の `VER`、本体の `APPVER`、`sw.js` の `VER` を**同じ版番号**に揃える
   （揃っていないと `build.py` がビルドを失敗させる）
3. `python3 build.py` → `deploy/` が更新される
4. `deploy/` の中身をリポジトリへ push

### 入る側（iPad）

- 電波のある場所でアプリを起動すると、裏で新版がダウンロードされる
- **その場では切り替わらない。** 踏査の途中でアプリが入れ替わるのが最も危険なため、
  `skipWaiting` は呼んでいない
- 「新しい版があります」というトーストが出たら、**アプリを完全に終了**（App Switcher から
  上スワイプ）して起動し直すと新版になる
- ☰メニュー最下部の版番号で確認できる

> GitHub Pages の CDN は最大 10 分程度キャッシュする。push 直後に反映されないことがある。

## 5. オフライン運用の注意

- **初回だけはネットワークが必要。** それ以降は完全にオフラインで動く
- スケッチの自動保存は IndexedDB。ホーム画面アプリなら iOS の 7 日削除の対象外だが、
  **踏査が終わったら ZIP / バンドルで書き出して端末外へ退避すること**を運用ルールにする
- iPadOS のストレージ逼迫時は、OS 判断でキャッシュが破棄されることがある
- Service Worker が使えない古い iPadOS（11.3 未満）ではオフライン起動できない。
  その場合は `index.html` を直接ダウンロードして Files アプリから開く運用にする

---

## 6. 単一 HTML だけを配りたい場合

`index.html` をダウンロードして AirDrop / MDM / メール添付で配れば、
サーバ無しでそのまま動く。この場合 Service Worker は登録されず、
ブラウザのタブ（または Files アプリ）から開く運用になる。
